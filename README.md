## 简介

**MinecraftTransitDriver（MTR驾驶进阶）** 是一个面向 MTR 驾驶员的轻量级客户端扩展模组。它把「开哪一侧车门」的控制权交还给驾驶员：在驾驶列车时，用 **左方向键** 打开列车运行方向左侧车门，用 **右方向键** 打开右侧车门；两个按键都可以在 Minecraft 的「控制」设置中自由修改。

同时，本模组针对 MTR 原版「没有站台方块时车门不显示打开」的问题做了处理：使用左右开门键时，即使车站没有铺设站台方块，列车也会完整播放开门动画并完全打开对应侧车门。

模组不新增方块、物品或列车，只增强驾驶时的车门控制，因此可以与绝大多数 MTR 车站、列车和装饰模组共同使用。

## 功能特性

| 功能 | 说明 |
| --- | --- |
| 左侧开门 | 默认按 **左方向键**，打开列车运行方向左侧车门 |
| 右侧开门 | 默认按 **右方向键**，打开列车运行方向右侧车门 |
| 再次按键 | 再次按同一方向键可关闭该侧车门 |
| 无站台也开门 | 手动开门时不检查站台方块，动画完整播放并完全打开 |
| 可自定义按键 | 在「选项 → 控制 → 按键绑定」中修改，分类为 **MTR驾驶进阶** |
| 状态提示 | 每次操作后在动作栏显示「车门状态：左 开 / 右 关」 |
| 安全保护 | 列车未停稳、未驾驶列车、驾驶钥匙无开门权限时不会执行，并给出提示 |
| 原版兼容 | 不取代 MTR 的自动开关门逻辑；手动控制只在需要时覆盖对应车门 |

## 运行环境

| 项目 | 要求 |
| --- | --- |
| Minecraft | **1.20.4** |
| 模组加载器 | **Fabric Loader**（1.20.4 对应版本，建议 0.15.0 或更高） |
| Fabric API | **1.20.4 对应版本**（必须安装） |

| Java | **17 或更高** |

> 本模组声明了 `environment: client`。安装在专用服务器上时会被忽略，不会导致服务器启动失败。

## 安装步骤

1. 为 Minecraft **1.20.4** 安装 **Fabric Loader**。
2. 将 **Fabric API** 放入 `.minecraft/mods` 文件夹。
3. 将 **MTR 4.0.5+1.20.4** 的 Fabric 版本放入 `.minecraft/mods` 文件夹。
4. 将本模组文件放入同一个 `mods` 文件夹：

   ```text
   [MinecraftTransitDriver]1.20.4fabric_1.4.0beta.jar
   ```

5. 启动 Minecraft。进入游戏后，在「选项 → 控制 → 按键绑定」中可以看到 **MTR驾驶进阶** 分类。

> 请勿同时安装其他会修改 MTR 车门渲染逻辑的模组，否则可能出现车门动画冲突。

---

## 按键设置

1. 打开 **选项 → 控制 → 按键绑定**。
2. 找到分类 **MTR驾驶进阶**。
3. 修改以下两项：

   | 按键名称 | 默认按键 | 作用 |
   | --- | --- | --- |
   | 开/关左侧车门 | **左方向键** | 打开或关闭列车运行方向左侧车门 |
   | 开/关右侧车门 | **右方向键** | 打开或关闭列车运行方向右侧车门 |

4. 点击「保存」或直接返回即可生效。

### 关于 MTR 默认开门键

MTR 原版的「列车开门/关门」默认键也是 **左方向键**。本模组会在检测到左右开门键被按下时，接管本次开门操作，避免同一次按键触发两次开关门。

如果你仍想使用 MTR 原版的「一键同时切换两侧车门」功能，请在按键设置中把 MTR 的「列车开门/关门」改到其他按键；单独按下该键时，本模组会恢复 MTR 原版的自动/平台判断行为。

> **关于 ATO 切换：** MTR 4.0.5 将「列车开门/关门」键同时用于 ATO 切换（同一个按键）。为了避免按左方向键开门时误切换 ATO，本模组在使用左右开门键时会同时抑制这次按键对 MTR 原版车门和 ATO 的触发。若你需要切换 ATO，请把 MTR 的「列车开门/关门」改到另一个按键并单独按下该键。

## 使用方法

### 前置条件

- 你正在**驾驶**列车（坐在驾驶位并手持有效驾驶钥匙）。
- 列车已经**停稳**（速度接近 0）。
- 驾驶钥匙具有**车门控制权限**（普通驾驶钥匙通常具备；部分特殊钥匙可能没有）。

### 开门

1. 将列车停稳在车站或任意需要开门的位置。
2. 按 **左方向键**：打开列车运行方向左侧车门。
3. 按 **右方向键**：打开列车运行方向右侧车门。
4. 动作栏会显示当前状态，例如：

   ```text
   车门状态：左 开 / 右 关
   ```

### 关门

- 再次按同一侧的方向键即可关闭该侧车门。
- 如果两侧都关闭，列车会通过 MTR 的关门动画平滑关闭两侧车门。
- 如果只关闭其中一侧、另一侧仍保持打开，被关闭的一侧会立即收起（不播放单独的关门动画），这是 MTR 共享车门动画值带来的限制。

### 无站台方块时开门

- 使用左右开门键时，本模组会跳过「附近是否有站台方块」的检查。
- 即使没有铺设 MTR 站台方块，车门也会完整播放开门动画并完全打开。
- 该行为只作用于**玩家正在驾驶的列车**。完全无人的 ATO 列车仍遵循 MTR 原版自动门逻辑。

### 失败提示

| 动作栏提示 | 原因 |
| --- | --- |
| 请先驾驶列车 | 当前没有检测到你正在驾驶的列车 |
| 请手持有效的驾驶钥匙 | 手上没有该车库/车辆可用的驾驶钥匙 |
| 该驾驶钥匙无法控制车门 | 当前钥匙没有开门权限 |
| 请先停稳列车 | 列车仍有速度，出于安全考虑拒绝操作 |

## 门侧定义

本模组中的「左/右」指**列车运行方向上的左/右**，也就是从列车前部朝行进方向看时的左右两侧。

模组通过 MTR 列车模型中的标准 `flipped`（左右镜像）属性判断车门属于哪一侧。绝大多数 MTR 原版列车和遵循 MTR 资源规范的追加列车都能正确识别。

如果你使用的自定义列车模型没有遵循该规范，可能出现左右方向相反的情况。遇到这种情况请记录列车名称、模型来源和游戏日志，向模组作者反馈。

---

## 无站台方块开门

使用左右开门键时，本模组会跳过「附近是否有站台方块」的检查。即使没有铺设 MTR 站台方块，车门也会完整播放开门动画并完全打开。

- 该行为只作用于**玩家正在驾驶的列车**。
- 完全无人的 ATO 列车仍遵循 MTR 原版自动门逻辑。
- 如果车站有站台方块，手动开门同样生效，并可以只开指定一侧。
- 站台屏蔽门（PSD/APG）存在时，手动开门侧仍会执行 MTR 原版检测，但开门请求会覆盖该检测的阻止结果；手动关闭侧会跳过该侧检测，以避免误开对应侧的屏蔽门。请提前确认现场安全。

## 多人游戏说明

- 本模组的左右门状态保存在**驾驶端玩家自己的客户端**中。
- 开门/关门的全局状态仍通过 MTR 原版网络包同步，因此其他玩家会看到列车车门整体开/关。
- 但由于其他玩家没有你的左右门选择状态，他们看到的车门侧别可能仍按 MTR 原版规则（例如只开站台侧，或在无站台时不显示开门）。
- 专用服务器**不需要**安装本模组；即使安装也会因 `environment: client` 而被忽略。
- 如果服务器上有其他玩家驾驶同一列车，请以实际驾驶员客户端显示为准。

> 后续版本计划加入左右门状态同步，让多人游戏中的所有玩家看到一致的车门侧别。

## 与原版 MTR 的关系

本模组不会修改以下 MTR 行为：

- 列车自动停站与自动开关门逻辑；
- 站台屏蔽门（PSD/APG）在未手动控制车门时的默认联动；
- 列车行驶、信号、路线和时刻表；
- 驾驶钥匙的获取与权限判定。

只有在驾驶员主动按下左右开门键，或为了播放无站台开门动画时，才会临时覆盖车门渲染判断。

## 常见问题

### Q：按方向键没有反应？

请依次确认：

1. Minecraft 是 **1.20.4**，Fabric Loader 和 Fabric API 均已安装。
2. MTR 是 **4.0.5+1.20.4**，不是 1.20.1 或其他版本。
3. 你正在**驾驶**列车，而不是以乘客身份乘坐。
4. 列车已经停稳。
5. 手持的驾驶钥匙具有开门权限。
6. 「选项 → 控制」中没有把左右开门键绑定到冲突按键。

### Q：为什么左方向键同时是 MTR 的开门键？

MTR 原版的开门键默认就是左方向键。本模组已处理该冲突：按下左方向键时优先执行「打开/关闭左侧车门」，并抑制 MTR 原版同一次按键的重复切换。你也可以在控制设置中把两者改成不同按键。

### Q：没有站台方块，为什么自动停站时车门还是不显示打开？

本版本的「无站台也开门」通过左右开门键触发。请在列车停稳后按左/右方向键开门。完全无人的 ATO 列车仍使用 MTR 原版逻辑。

### Q：关门时为什么有一侧是瞬间收起？

MTR 所有车门共享同一个开门动画值。当另一侧仍然打开时，本模组只能把当前侧的车门动画归零，因此表现为瞬间收起。两侧都关闭时，会使用 MTR 的正常关门动画。

### Q：左右方向反了怎么办？

这通常说明自定义列车模型的 `flipped` 约定与 MTR 标准不一致。请反馈列车模型名称和来源；在修复前可以暂时通过交换左右开门键来适应。

### Q：会影响存档或服务器吗？

不会。本模组不新增方块/物品，也不修改存档数据。服务器不需要安装；客户端卸载后存档可正常使用。

## 从源码构建

项目使用 Fabric Loom 1.10.5 与 Gradle 8.12。

```bash
# Windows
gradlew.bat build

# macOS / Linux
./gradlew build
```

构建产物位于：

```text
build/libs/[MinecraftTransitDriver]1.20.4fabric_1.4.0beta.jar
```

> 项目依赖（MTR、Fabric API、Fabric Loader）不会被打包进最终模组。发布时请让玩家自行安装对应依赖；`libs/` 中的 MTR jar 用于本地编译。
